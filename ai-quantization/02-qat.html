QAT — 量化感知训练

定义：在训练过程中模拟量化误差，让模型学会抗量化

发明人与背景

QAT（Quantization-Aware Training）不是单一论文发明，而是一条演化路线：Bengio 等人在 2013 年推动了 Straight-Through Estimator, STE 的离散训练思路；PACT（2018）开始学习激活裁剪边界；LSQ（2020，Facebook/Meta）进一步把量化 step size 学成参数。QAT 的兴起原因很直接：很多小模型或高要求业务中，朴素 PTQ 精度不够。

核心原理

QAT 像学钢琴时戴着手套练习：训练阶段刻意制造“动作受限”的环境，真正演出时反而更稳。这里的“手套”就是 Fake Quantization。

关键在 STE：前向传播使用量化值，反向传播时把量化节点近似为恒等映射，从而绕过不可微的 round/clamp。

基本方法

1

插入 FakeQuantize 节点

在权重、激活或关键算子周围加入模拟量化节点，但底层仍存 FP32/FP16 参数。

2

前向传播使用量化数值

通过 round、clamp、scale 让网络在训练阶段就感受到低比特误差。

3

反向传播使用 STE

把不可微量化函数替换为近似可导路径，让梯度继续更新原始参数。

4

收敛后移除 FakeQuantize 节点

训练结束后把 learned scale 等参数固化到最终导出图。

5

导出量化模型

导出 INT8/INT4 权重与部署图，供 TensorRT、TFLite、ONNX Runtime 等后端使用。

def fake_quant(x, scale, qmin=-128, qmax=127):
    q = (x / scale).round().clamp(qmin, qmax)
    return q * scale

class STEQuant(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale):
        return fake_quant(x, scale)

    @staticmethod
    def backward(ctx, grad_output):
        return grad_output, None

实施难点

梯度消失：过度裁剪或过低 bit 容易让可学习信号变差。

超参数敏感：learning rate、warmup、clip range、group size 都可能影响最终精度。

LLM 成本极高：对几十亿甚至上百亿参数再训练，算力成本显著高于 PTQ。

量化粒度选择：per-token、per-channel、group-wise 设计会影响稳定性与 kernel 复杂度。

学术前沿

LLM-QAT (Meta, 2023)

把 QAT 推向大模型，证明适当训练可显著恢复低比特精度。

QuaRot (2024)

引入旋转减少异常通道，让量化更“均匀”。

EfficientQAT (2024)

关注减少重训练成本，让量化感知训练更接近工程可用。

BitNet b1.58 (2024)

把超低比特训练推向新的讨论热点，探索训练与量化的一体化。

对比

QAT vs PTQ

QAT 更慢、更贵，但通常精度更高，特别适合小模型、语音模型、检测模型或高精度业务。

QAT vs GPTQ

GPTQ 是高质量 PTQ，更适合无训练资源的 LLM 部署；QAT 则适合有训练闭环、追求极致精度的团队。
