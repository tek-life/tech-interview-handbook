FP8 — 浮点8位量化新范式

定义：保留浮点动态范围，GPU原生支持，兼顾训练与推理

发明人与背景

FP8 由 Paulius Micikevicius 等（NVIDIA + ARM + Intel）在 2022 年系统提出，论文为 FP8 Formats for Deep Learning。它不是传统 INT 量化，而是把“低比特”和“浮点动态范围”结合起来，特别适合现代 GPU 原生加速。

核心原理

FP8 像两种相机模式：E4M3 像人像模式，细节更好，适合 inference；E5M2 像风景模式，范围更大，适合 gradient 与 training。

E4M3 = 4 exponent bits + 3 mantissa bits，范围约 ±448；E5M2 = 5 exponent bits + 2 mantissa bits，范围约 ±57344。相比 INT8，FP8 仍保留 exponent，因此更擅长处理动态范围跨度大的张量。

基本方法

1

选择格式

Inference 中常用 E4M3 处理权重/激活；Training 中常用 E5M2 处理梯度。

2

设置 per-tensor scaling

用额外 scale 管理不同张量的动态范围，避免下溢/上溢。

3

启用 Transformer Engine

借助 NVIDIA Transformer Engine 自动完成 cast、amax 统计与缩放更新。

4

混合精度运行

累加常保持更高精度，如 FP16/BF16/FP32 accumulator。

5

监控数值稳定性

持续跟踪 overflow、underflow 和 loss spike。

import transformer_engine.pytorch as te

fp8_recipe = te.common.recipe.DelayedScaling(
    fp8_format=te.common.recipe.Format.HYBRID,
    amax_history_len=16,
)
with te.fp8_autocast(enabled=True, fp8_recipe=fp8_recipe):
    output = model(input_ids)

实施难点

E4M3 vs E5M2 策略：不同张量该选哪个格式，不是固定答案。

Scaling factor 管理：FP8 仍需要良好的 amax 追踪和 scale 更新策略。

硬件支持：H100 / H200 / Blackwell 等新 GPU 支持更完善，较老 GPU 往往无法原生 FP8 加速。

学术前沿

Transformer Engine (NVIDIA, 2023)

把 FP8 从论文概念推进到实际大规模训练框架。

FP8-LM (2023)

探索语言模型全流程 FP8 化的数值策略。

MX / Microscaling (2023)

研究更灵活的低位宽浮点格式与共享缩放机制。

DeepSeek FP8 训练 (2024)

大规模模型训练开始更积极采用 FP8，以追求吞吐与成本优势。

对比

FP8 vs INT8

INT8 依赖 scale，把浮点映射成整数；FP8 直接保留 exponent，因此对动态范围更友好，但需要硬件支持。

FP8 vs FP16

FP8 更省显存、更快，但数值更脆弱；FP16/BF16 仍是很多任务中的稳健基线。
